# Авансовые отчёты

Клиент-серверная программа для **заполнения, печати и отправки по почте авансовых отчётов**.
Сделана на основе формы Excel `Авансовый Кухаренко.xlsm` (ООО «Сэйлз Модерн групп»):
печатный бланк полностью повторяет исходную форму, а данные хранятся в базе данных на сервере.

## Возможности

| Раздел | Что умеет |
|---|---|
| **Отчёты** | Создание авансового отчёта по форме: дата, подотчётное лицо, должность, назначение аванса, до 3 полученных авансов и до 10 строк расходов |
| **Печать** | Готовый бланк A4 «Отчет об израсходованных суммах» — печать из браузера, с подписями и суммой прописью |
| **Excel** | Выгрузка заполненного бланка в `.xlsx` (лист «Отчет к заполнению» исходного файла) |
| **Почта** | Отправка ответственному сотруднику: письмо с HTML-сводкой и вложенным Excel-бланком |
| **Права** | Пользователь видит **только свои** отчёты; супервайзер и администратор — **все** |
| **Удаление** | Удалять отчёты может **только администратор** |
| **Пользователи** | Создают супервайзер и администратор (из интерфейса) |
| **Неизменяемость** | Сохранённый отчёт **нельзя отредактировать** — только создать новый (закреплено триггером в БД) |
| **Обновления** | Кнопка «Проверить обновления» в интерфейсе; сборка на GitHub Actions. **База данных при обновлении сохраняется** |
| **Безопасность** | Пароли — PBKDF2-SHA256 (210 000 итераций), сессии с истечением, защита от перебора, журнал действий |
| **Резервные копии** | Автоматически раз в сутки + вручную + перед каждым обновлением |

## Быстрый старт

### Вариант 1. Готовая сборка для Windows

1. Откройте [Releases](https://github.com/zigorminsk-debug/Avans-Report/releases) и скачайте
   `AvansReport-Setup-<версия>.exe`.
2. Запустите установщик (нужны права администратора).
3. Запустите программу ярлыком **«Авансовые отчёты»** — откроется браузер,
   где нужно создать учётную запись администратора.
4. В разделе **«Настройки»** заполните организацию, подписи, адрес ответственного
   и параметры SMTP-сервера.
5. В разделе **«Пользователи»** создайте учётные записи сотрудников.

### Вариант 2. Запуск из исходного кода

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate

pip install -r requirements.txt
python desktop/launcher.py            # локальный запуск, откроется браузер
```

Открыть интерфейс: <http://127.0.0.1:8770>

### Режим сервера (несколько сотрудников)

```bash
python desktop/launcher.py --host 0.0.0.0 --port 8770 --no-browser
```

Сотрудники открывают в браузере `http://IP-сервера:8770`.
Сервер можно поставить как службу:

* **Windows** — при установке поставьте галочку «Запускать при входе в Windows (режим сервера)»
  и «Разрешить доступ с других компьютеров локальной сети»;
* **Linux** — `sudo ./installer/linux/install-server.sh AvansReport-Linux-x86_64-<версия>.tar.gz`
  (создаёт пользователя, каталог данных `/var/lib/avansreport` и службу systemd).

Для доступа через интернет укажите в `config.json` пути к сертификату и ключу
(`tls_cert`, `tls_key`) — сервер поднимется по HTTPS.

## Роли и права

| Действие | Пользователь | Супервайзер | Администратор |
|---|:--:|:--:|:--:|
| Создавать отчёты | ✅ | ✅ | ✅ |
| Видеть свои отчёты | ✅ | ✅ | ✅ |
| Видеть отчёты всех сотрудников | — | ✅ | ✅ |
| Печать и выгрузка в Excel | свои | все | все |
| Отправка по почте | свои | все | все |
| Удаление отчёта | — | — | ✅ |
| Создание пользователей | — | ✅ (только «Пользователь») | ✅ (любая роль) |
| Блокировка/разблокировка, смена ФИО и ролей | — | — | ✅ |
| Сброс пароля пользователя | — | ✅ (только «Пользователь») | ✅ |
| Удаление пользователя | — | — | ✅ |
| Настройки, SMTP, резервные копии, журнал | — | — | ✅ |
| Установка обновления из интерфейса | — | — | ✅ |

Ограничения, заложенные в код:

* сохранённый отчёт нельзя изменить — нет методов `PUT/PATCH` для отчёта,
  а в SQLite стоит триггер `reports_immutable`, который отменяет `UPDATE`;
* пользователя, у которого есть отчёты, нельзя удалить (можно только заблокировать);
* нельзя заблокировать или удалить самого себя, нельзя удалить последнего администратора.

## Как это работает

```
┌──────────────────┐        HTTP(S)         ┌────────────────────────────┐
│  Клиент          │  ───────────────────▶  │  Сервер (FastAPI/Uvicorn)  │
│  HTML + JS       │  ◀───────────────────  │  • авторизация и сессии    │
│  (браузер)       │        JSON            │  • права и валидация       │
└──────────────────┘                        │  • печатный бланк, Excel   │
                                            │  • отправка почты (SMTP)   │
                                            │  • проверка обновлений     │
                                            └────────────┬───────────────┘
                                                         │
                                                 ┌───────▼────────┐
                                                 │ SQLite         │
                                                 │ avans.db       │
                                                 └────────────────┘
```

* **Клиент** — одностраничное приложение без сборки (`app/static/`), открывается
  в любом современном браузере. Нужен только адрес сервера.
* **Сервер** — Python + FastAPI. Работает локально (один компьютер) или в сети.
* **База** — SQLite в каталоге данных пользователя, вне каталога установки.

### Где хранятся данные

| ОС | Каталог |
|---|---|
| Windows | `%APPDATA%\AvansReport` |
| macOS | `~/Library/Application Support/AvansReport` |
| Linux | `~/.local/share/AvansReport` |

Внутри: `avans.db` (база), `backups/` (резервные копии), `config.json` (настройки
запуска), `avans-report.log` (журнал), `updates/` (скачанные установщики).
Каталог можно задать переменной окружения `AVANS_DATA_DIR`.

**Обновление программы не затрагивает эти файлы** — установщик работает только
с каталогом программы, а перед обновлением дополнительно создаётся резервная копия базы.

## Обновления с GitHub

1. Кнопка **«Проверить обновления»** в левом нижнем углу интерфейса.
2. Программа обращается к GitHub Releases репозитория `zigorminsk-debug/Avans-Report`.
3. Если версия новее — показываются название релиза, список изменений и кнопка
   **«Установить и перезапустить»** (только администратор, только Windows-сборка).
4. Перед установкой сервер:
   * создаёт резервную копию базы (`backups/avans-<дата>-before-update.db`);
   * скачивает установщик;
   * запускает его в тихом режиме — программа переустанавливается и перезапускается.

В остальных случаях (Linux/macOS, запуск из исходников) показывается ссылка на файл релиза.

### Как выпустить новую версию

```bash
git tag v1.0.2
git push origin v1.0.2
```

Тег запускает `.github/workflows/release.yml`, который:

1. прогоняет тесты;
2. подставляет версию в `app/version.py`;
3. собирает Windows-приложение (PyInstaller) и установщик (Inno Setup);
4. собирает архив для Linux;
5. **запускает собранную программу** и проверяет, что она отдаёт интерфейс
   и формирует бланк Excel (смоук-тест готовой сборки);
6. публикует релиз с файлами и контрольными суммами `SHA256SUMS.txt`.

Можно запустить и вручную: *Actions → Release → Run workflow* с указанием версии
(кнопка доступна, когда workflow есть в ветке `main`).

Актуальные сборки: [Releases](https://github.com/zigorminsk-debug/Avans-Report/releases).
Версия в `app/version.py` носит справочный характер — при сборке она
подставляется из тега.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -q                       # тесты
python -m uvicorn app.main:app --reload   # сервер с авто-перезагрузкой
# API-документация: http://127.0.0.1:8000/api/docs
```

Проверка синтаксиса интерфейса: `node --check app/static/app.js`.

### Сборка установщика вручную (Windows)

```powershell
pip install -r requirements-dev.txt
pyinstaller --noconfirm --clean desktop/AvansReport.spec
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\windows\AvansReport.iss
# результат: dist\installer\AvansReport-Setup-<версия>.exe
```
