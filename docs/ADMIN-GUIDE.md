# Руководство администратора

## 1. Установка

### Windows (установщик)

1. Скачайте `AvansReport-Setup-<версия>.exe` со страницы [Releases](https://github.com/zigorminsk-debug/Avans-Report/releases).
2. Запустите установщик, примите лицензию, выберите каталог (по умолчанию `C:\Program Files\AvansReport`).
3. Дополнительные галочки:
   * **ярлык на рабочем столе**;
   * **автозапуск при входе в Windows** — нужен, если компьютер работает как сервер;
   * **разрешить доступ с других компьютеров локальной сети** — создаёт правило
     брандмауэра для порта 8770.
4. После установки запустите программу — откроется браузер с созданием администратора.

### Linux (сервер)

```bash
tar -xzf AvansReport-Linux-x86_64-<версия>.tar.gz
sudo ./installer/linux/install-server.sh AvansReport-Linux-x86_64-<версия>.tar.gz
```

Скрипт создаёт:
* пользователя `avansreport`;
* каталог программы `/opt/avansreport`;
* каталог данных `/var/lib/avansreport`;
* службу systemd `avansreport` (автозапуск, перезапуск при сбое).

Полезные команды:

```bash
systemctl status avansreport
journalctl -u avansreport -f        # журнал
systemctl restart avansreport
```

### Запуск из исходного кода

```bash
pip install -r requirements.txt
python desktop/launcher.py --host 0.0.0.0 --port 8770 --no-browser
```

## 2. Первичная настройка

При первом открытии программа попросит создать администратора:

* **Организация** — попадёт в шапку бланка;
* **ФИО администратора**, **логин**, **пароль** (не менее 8 символов, буквы и цифры).

Далее в разделе **«Настройки»**:

| Поле | Назначение |
|---|---|
| Организация | наименование в шапке бланка и в письмах |
| Должность и ФИО руководителя | блок «УТВЕРЖДАЮ» |
| Должность и ФИО бухгалтера | строка подписи бухгалтера |
| Ответственный по умолчанию | адрес, который подставляется при отправке |
| Назначение аванса | варианты выпадающего списка (по одному в строке) |
| Время жизни сессии | через сколько часов требуется повторный вход (по умолчанию 12) |

## 3. Настройка почты (SMTP)

Заполните параметры сервера. Примеры для популярных служб:

| Служба | Сервер | Порт | Защита |
|---|---|---|---|
| Яндекс (с паролем приложения) | `smtp.yandex.ru` | 465 | SSL/TLS |
| Mail.ru | `smtp.mail.ru` | 465 | SSL/TLS |
| Gmail (пароль приложения) | `smtp.gmail.com` | 587 | STARTTLS |
| Корпоративный Exchange | `mail.company.by` | 587 | STARTTLS |
| Внутренний сервер без шифрования | `192.168.0.10` | 25 | Без шифрования |

Порядок:

1. Укажите сервер, порт и тип защиты.
2. Логин и пароль — обычно полный адрес почты и пароль приложения
   (для Gmail/Яндекс обычный пароль не подойдёт, нужен «пароль приложения»).
3. **Адрес отправителя** — должен совпадать с логином, иначе сервер отклонит письмо.
4. Сохраните настройки и нажмите **«Отправить тестовое письмо»**
   (адрес берётся из поля «Ответственный по умолчанию»).

Типичные ошибки:

| Сообщение | Причина / решение |
|---|---|
| `SMTP-сервер отклонил логин или пароль` | неверный логин/пароль, нужен пароль приложения |
| `Не удалось подключиться к SMTP-серверу` | блокировка порта, неверный адрес, требуется VPN |
| `SMTP-сервер не принял письмо` | адрес отправителя не совпадает с логином, лимит отправки |
| `Не настроен SMTP` | не заполнены поля в разделе «Настройки» |

## 4. Пользователи

Раздел **«Пользователи»** (администратор и супервайзер).

* **Создать пользователя** — логин, ФИО, должность, e-mail, роль, пароль.
  При первом входе пользователь увидит напоминание сменить пароль.
* **Пароль** — задать новый пароль (сессии пользователя закрываются).
* **Заблокировать / Разблокировать** — учётная запись отключается без потери отчётов.
* **Удалить** (только администратор) — доступно лишь для пользователей без отчётов;
  если отчёты есть, используйте блокировку.

Правила:

* супервайзер создаёт только пользователей с ролью «Пользователь»
  и может лишь задавать им пароли;
* нельзя заблокировать или удалить самого себя;
* нельзя удалить последнего администратора.

## 5. Резервные копии и восстановление

Где лежат данные:

| ОС | Каталог |
|---|---|
| Windows | `%APPDATA%\AvansReport` |
| Linux | `/var/lib/avansreport` (при установке скриптом) |
| macOS | `~/Library/Application Support/AvansReport` |

Автоматика:

* **раз в сутки** создаётся копия `backups/avans-<дата>-auto.db`;
* **перед обновлением** — `backups/avans-<дата>-before-update.db`;
* хранятся последние 20 копий.

Вручную: **Настройки → Резервная копия** (создать) и **Скачать базу**
(скачать файл `avans-*.db` на свой компьютер — удобно для архива).

Восстановление:

1. Остановите службу/программу.
2. Скопируйте нужный файл из `backups/` в каталог данных под именем `avans.db`
   (старый `avans.db` предварительно переименуйте).
3. Удалите файлы `avans.db-wal` и `avans.db-shm`, если они есть.
4. Запустите программу.

## 6. Обновления

Кнопка **«Проверить обновления»** в интерфейсе (раздел доступен всем, установка — администратору).

Что происходит при установке:

1. создаётся резервная копия базы;
2. скачивается установщик из GitHub Releases;
3. установщик запускается в тихом режиме, программа перезапускается.

База данных хранится отдельно от программы, поэтому **обновление не удаляет отчёты**.
Если обновление не удалось, просто запустите установщик из Releases вручную —
поведение будет тем же.

Чтобы выпустить релиз:

```bash
git tag v1.0.2
git push origin v1.0.2
```

GitHub Actions соберёт установщик, архив для Linux, **запустит собранную программу
и проверит интерфейс и формирование бланка**, затем опубликует релиз
с контрольными суммами. Готовые файлы — на странице Releases.

## 7. Безопасность

* Пароли хранятся как PBKDF2-SHA256 (210 000 итераций, случайная соль).
* Сессии — случайный токен, в базе хранится только его SHA-256; срок жизни настраивается.
* 10 неудачных попыток входа за 10 минут блокируют пару «логин + IP».
* Все значимые действия пишутся в журнал (**Настройки → Журнал действий**):
  входы, создание и удаление отчётов, отправка писем, изменения пользователей и настроек.
* Сохранённый отчёт неизменяем на уровне базы (триггер).
* Внутри локальной сети трафик идёт по HTTP. Для доступа через интернет
  настройте HTTPS (`tls_cert`, `tls_key` в `config.json`) или поставьте
  reverse-proxy (nginx/Caddy) с сертификатом.

## 8. Файл config.json

Лежит в каталоге данных, создаётся при первом запуске:

```json
{
  "host": "0.0.0.0",
  "port": 8770,
  "open_browser": false,
  "remote_url": "",
  "tls_cert": "",
  "tls_key": "",
  "allow_self_update": true
}
```

| Ключ | Значение |
|---|---|
| `host` | `127.0.0.1` — только этот компьютер; `0.0.0.0` — доступ по сети |
| `port` | порт (если занят, программа возьмёт следующий свободный) |
| `open_browser` | открывать браузер при запуске |
| `remote_url` | режим клиента: адрес уже работающего сервера, локальный сервер не запускается |
| `tls_cert`, `tls_key` | пути к сертификату и ключу для HTTPS |
| `allow_self_update` | разрешить установку обновлений из интерфейса |

Переменные окружения: `AVANS_DATA_DIR` — каталог данных.

## 9. Устранение неполадок

**Браузер не открылся.**
Откройте вручную `http://127.0.0.1:8770`. Если страница недоступна — посмотрите
журнал: `%APPDATA%\AvansReport\avans-report.log`.

**Порт занят.**
Программа автоматически выбирает следующий свободный порт; фактический адрес
пишется в журнал. Можно задать порт явно: `AvansReport.exe --port 8080`.

**Сотрудники не могут подключиться.**
Проверьте: `host = 0.0.0.0` в `config.json`, правило брандмауэра для порта,
доступность `http://IP-сервера:8770` с другого компьютера.

**Забыт пароль администратора.**
Создайте нового администратора из командной строки на сервере:

```bash
python - <<'PY'
from app import db
from app.security import hash_password
with db.transaction() as conn:
    conn.execute("UPDATE users SET password_hash = ?, is_active = 1 WHERE username = 'admin'",
                 (hash_password("НовыйПароль123"),))
print("пароль обновлён")
PY
```

Для сборки-исполняемого файла используйте тот же скрипт, запустив его из каталога
программы интерпретатором Python, либо обратитесь к резервной копии.

**Диск заполнен.**
Очистите каталог `backups/` (оставьте несколько последних копий) и `updates/`.

**Нужно перенести программу на другой сервер.**
Скопируйте каталог данных целиком (или только `avans.db`), установите программу
на новом сервере и запустите её, указав `AVANS_DATA_DIR` на скопированный каталог.
